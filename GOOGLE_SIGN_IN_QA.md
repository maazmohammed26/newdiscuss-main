## Native sign-in cause and configuration correction

The affected Android screenshot reported `G2/native-no-credentials/callback`: the native bridge returned a no-credentials error before Firebase credential exchange.

The Google Cloud Android OAuth client shown by the user registered the Median/upload certificate. The Google Play app-signing certificate supplied by the user was different:

| Setting | Value |
| --- | --- |
| Android package | `co.median.android.lpowadz` |
| Median/upload SHA-1 | `B0:BE:47:9A:08:7D:84:58:BB:9E:94:9E:44:C6:06:5D:9A:8C:DD:9E` |
| Google Play app-signing SHA-1 | `F8:8F:D9:F1:19:4E:45:60:47:D3:B3:B8:36:26:EB:06:C9:86:56:D9` |

Correction: register an additional **Android OAuth client** for that package and the **Google Play app-signing SHA-1**, in the same project as the Web client configured in Median. Suggested client name: `Discuss Google Play`. Preserve the Median-certificate Android client for directly distributed APKs. Keep Median's Web Client ID and the working Web OAuth configuration unchanged. Do not replace or reset either signing key.

The user's subsequent successful test supports the certificate-registration mismatch as the cause of the reported Play-installed app failure. License expiry was not established as the cause. Account entitlement and broad device compatibility are not certified by this result.

Read-only inspection also found that the repository's older bundled APK lacks a Social Login service entry, while later APK/AAB downloads include the plugin and a matching Google client ID. This establishes build-configuration differences, but does not establish which historical build each user had installed.

## Separate web defects corrected

The screenshot is generated by `AuthContext.js`, before Firebase credential exchange. Commit `7d5045f` (August 27, 2026) removed recovery after native failures and replaced every non-cancellation error with advice to update Play services. That regression hides the cause and leaves affected users without recovery. It is not evidence of a Firebase server outage.

The recovery and diagnostic changes address web handling around native failures. They do not alter the SDK in an installed APK or register its certificate with Google OAuth.

## Changes

- Native sign-in remains the first choice on every normal attempt; cancellation does not open another flow.
- Categorized native failures offer an explicit browser recovery button on login and registration. No six-hour fallback flag or automatic browser jump is introduced.
- Native callbacks handle null/malformed responses, promise rejections, synchronous exceptions, timeouts and duplicate/late responses. Console diagnostics contain categories rather than tokens.
- Browser recovery transfers only AES-256-GCM ciphertext through `webViewAuth`. A random key is passed in a URL fragment and immediately removed from browser history. The app retains the key in memory. Flow ID binding and a two-minute expiry prevent cross-flow substitution and stale reuse. Google credentials are still verified by Firebase.
- The listener handles permission errors, duplicate responses and expiry; cleanup is best effort. Browser copy does not claim the app has signed in before it actually completes.

## September 6 diagnostic follow-up

The initial updated fallback screenshot contained only a generic error. A subsequent screenshot exposed `G2/native-no-credentials/callback`, which directed the investigation toward the native credential request and Android OAuth registration.

Native failures now display an allowlisted reference: `G2/<category>/<stage>`. Categories distinguish explicit license restrictions, unsupported native login, missing credentials, missing tokens, configuration, network, timeout and unknown errors. Stages distinguish callback, synchronous bridge exception, rejected bridge promise and timeout. Nested error fields and sibling numeric status codes are preserved for classification. No raw callback, token, email or arbitrary vendor message is displayed or sent to telemetry. An unknown reference remains inconclusive and requires device/vendor diagnostics.

For future failures, collect the displayed reference and device/build information. A license category means the native error reported a restriction; it does not prove when a trial expired or that payment alone will resolve all configuration issues.

## Maintenance and remaining integration checks

1. Preserve both Android OAuth registrations. For future signing-key changes, register every applicable app-signing certificate before rollout. The separate Capacitor project's package is not the Median release package.
2. Keep the existing Median Web client configuration. If moving Google/Firebase projects later, review all native and web OAuth registrations together.
3. For a new native build, verify supported-device behavior and Median release notes. No native SDK rebuild was performed as part of the certificate-registration correction.
4. Test an actual Play-installed build on a working and an affected phone: choose an account, cancel, retry, lose connectivity, and use a device without a saved Google credential. Record Android/app versions and sanitized native error codes; never capture tokens.
5. Validate the deployed RTDB rules for the new relay schema. This repository does not include the deployed rules and they were not changed. The initiator must be able to read its unpredictable flow path, the authenticated browser must write a v2 envelope, and cleanup must be allowed. Existing rules requiring the old timestamp/uid/pending schema may need migration. **Do not make the entire database public.** Encryption protects credentials; it does not replace write validation, abuse controls or expired-record cleanup. A server-managed exchange with rate limiting is a future option if relay access cannot be safely supported.
6. Complete browser recovery end to end against staging, including permission denial, expired link, invalid ciphertext, app closure and Firebase rejection. Keys are intentionally memory-only: if the app/page is killed, restart the attempt. An already-dispatched Firebase authentication request cannot be cancelled by a JavaScript timer and may establish a valid session late; no second exchange or profile completion is initiated by an expired relay callback.
7. Deploy the website and bridge together. Old open recovery tabs using plaintext must restart sign-in. Native SDK changes require a separate Play rollout.
