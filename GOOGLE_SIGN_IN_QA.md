# Google sign-in investigation and release checks

## Confirmed findings

The screenshot is generated by `AuthContext.js`, before Firebase credential exchange. Commit `7d5045f` (August 27, 2026) removed recovery after native failures and replaced every non-cancellation error with advice to update Play services. That regression hides the cause and leaves affected users without recovery. It is not evidence of a Firebase server outage.

The user confirmed installation through Google Play. The affected Android version, app version, actual native callback error, Median project configuration and Play signing configuration were not available. The underlying device failure is therefore not yet confirmed.

Median documents both an Android OAuth SHA-1 configuration cause for missing account prompts and an April 21, 2026 native fix for Android 14 and below without a Google account. A website update cannot repair the native SDK packaged in an already-installed APK.

## Changes

- Native sign-in remains the first choice on every normal attempt; cancellation does not open another flow.
- Categorized native failures offer an explicit browser recovery button on login and registration. No six-hour fallback flag or automatic browser jump is introduced.
- Native callbacks handle null/malformed responses, promise rejections, synchronous exceptions, timeouts and duplicate/late responses. Console diagnostics contain categories rather than tokens.
- Browser recovery transfers only AES-256-GCM ciphertext through `webViewAuth`. A random key is passed in a URL fragment and immediately removed from browser history. The app retains the key in memory. Flow ID binding and a two-minute expiry prevent cross-flow substitution and stale reuse. Google credentials are still verified by Firebase.
- The listener handles permission errors, duplicate responses and expiry; cleanup is best effort. Browser copy does not claim the app has signed in before it actually completes.

## Verification performed

- 19 automated tests: native response handling, cancellation/error classification, delayed Median/GoNative discovery, timeout/late callback, encrypted roundtrip, wrong-key/wrong-flow rejection, tampering, plaintext rejection and expiry.
- Production build passes. Existing hook warnings remain in PulseFeed and SecurityLockScreen.
- Local login page rendered at http://127.0.0.1:3000/login.
- Independent QA review completed; no actual phone or Google account sign-in performed.

## Required before production rollout

1. In Google Play Console App Integrity, obtain the **app signing certificate** SHA-1 for the installed release (not only the upload certificate). Confirm an Android OAuth client matches that fingerprint and the actual Median package name. Include any rotated signing certificate used by affected devices. Do not assume the separate Capacitor project's package identifies the Median release.
2. Confirm Median Social Login uses the correct Web client ID in the same Google/Firebase project. Verify the Firebase Google provider is enabled.
3. Check the shipped Median native build includes the April 21 fix. Rebuild and distribute a new Play release if necessary, preserving the existing app signing identity.
4. Test an actual Play-installed build on a working and an affected phone: choose an account, cancel, retry, lose connectivity, and use a device without a saved Google credential. Record Android/app versions and sanitized native error codes; never capture tokens.
5. Validate the deployed RTDB rules for the new relay schema. This repository does not include the deployed rules and they were not changed. The initiator must be able to read its unpredictable flow path, the authenticated browser must write a v2 envelope, and cleanup must be allowed. Existing rules requiring the old timestamp/uid/pending schema may need migration. **Do not make the entire database public.** Encryption protects credentials; it does not replace write validation, abuse controls or expired-record cleanup. A server-managed exchange with rate limiting is a future option if relay access cannot be safely supported.
6. Complete browser recovery end to end against staging, including permission denial, expired link, invalid ciphertext, app closure and Firebase rejection. Keys are intentionally memory-only: if the app/page is killed, restart the attempt. An already-dispatched Firebase authentication request cannot be cancelled by a JavaScript timer and may establish a valid session late; no second exchange or profile completion is initiated by an expired relay callback.
7. Deploy the website and bridge together. Old open recovery tabs using plaintext must restart sign-in. Native SDK changes require a separate Play rollout.

This change fixes verified web defects and provides recovery; it is not a claim that the affected Play build's native chooser or live relay rules have been validated.
